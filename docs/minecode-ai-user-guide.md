# MineCode AI 用户指南

本指南面向玩家与服务器管理员，按“第一次用 → 日常使用 → 大型项目 → 出错怎么办 → 服务器管理”的顺序组织。安装方式见 [README](../README.md)，模型协议见 [AI 计划协议](ai-plan-protocol.md)。

---

## 1. 首次使用

### 1.1 打开控制台

进入世界后有两种入口：

- 按 **O** 键；
- 输入 `/minecode`。

两种入口等价。控制台是暂停无关的覆盖层，打开时游戏不会暂停。

### 1.2 填写接口配置

点顶部 **配置/档案** 打开配置页，填写三项：

| 字段 | 说明 |
|---|---|
| Endpoint | OpenAI 兼容地址。可填 `https://example.com/v1`、`https://example.com/v1/chat/completions`，或只填域名 |
| API Key | 只保存在客户端，不会随网络包发给服务器 |
| 模型 | 初始值只是占位，请填你所用服务商实际支持的模型名 |

保存后点 **返回** 回到控制台。

> 配置写在游戏目录 `config/minecode.json`。**该文件含明文密钥，不要分享或提交。**

### 1.3 思考强度

四档：**none / low / medium / high**。

- 选 `none` 时不会向服务发送 `reasoning_effort` 字段——**如果你的服务商不认这个参数，就选 none**。
- 手改配置文件填了这四档以外的值（如 `xhigh`），会被当作不支持而**静默不发送**，不会报错。请用界面按钮切换。

### 1.4 发第一个任务

在底部输入框输入任务，**Enter 发送**，**Shift+Enter 换行**。

例如：

```
在我附近设计一个 5×5 自动门
```

你会依次看到：主 Agent 排队/处理中 → 文本与公开思考摘要 →（可能）子 Agent 的独立进度 → 汇总后的最终计划 → 右侧出现逐条动作卡片。

**没有任何动作会自动执行。** 每条都要你点“确认”。

## 2. 档案、技能与记忆

### 2.1 档案（Profile）

一个档案 = 一组“身份设定”，包含名称、系统提示词、模型、思考强度和技能文本。可以建多个（如“建造助手”“红石工程师”），用 **切换档案** 轮换。

档案保存在客户端配置里，**跟随你的游戏客户端**，不跟随世界。

### 2.2 技能文本

技能是贴在档案里的长文本指令，支持多行。**多个技能用空行分隔**，保存后会按空行切回多条；往返多次不会丢内容。

### 2.3 世界记忆

记忆是**跟随世界**的（存在存档目录里），用于跨会话记住你的偏好。

记忆有两个来源：

1. AI 在计划里提出 `memoryDrafts` → 出现在右侧面板 → 你点 **确认写入记忆** 才生效；
2. 你手动写入。

记忆上限 **32 条**，超出时**自动淘汰最旧的一条**（不会丢报错），你可以在面板里查看当前版本号并在历史里回滚。

### 2.4 版本与回滚

每次记忆/技能变更都会 +1 版本，最多保留 **32 个历史版本**。面板底部列出历史版本，点 **回滚至此版本** 会恢复该版本的内容，**并创建一个新版本**（回滚本身也是可审计的）。

## 3. 子 Agent（派遣）

当任务足够大时，AI 可以自己提出 `delegations`，把工作分给最多 **3 个**子 Agent，每个显示角色、状态和输出，最后由汇总 Agent 合成**唯一**的最终方案。

几条硬规则（不是提示词约束，是代码约束）：

- 子 Agent **不能**再派遣；
- 子 Agent 的派遣请求会被忽略并给出提示；
- 一次任务最多 3 个子 Agent；
- 最终只有一个计划进入预览。

子 Agent 的完整结果会交给汇总 Agent，所以你看到的是合并后的方案，而不是三份并列方案。

## 4. 动作确认与撤销

### 4.1 三类动作

| 类型 | 含义 | 可撤销 |
|---|---|---|
| `PLACE_BLOCK` | 放置单个方块（可带方块状态） | 是 |
| `FILL` | 填充一个长方体区域 | 是 |
| `RUN_COMMAND` | 执行一条受限原版命令 | **否** |

`RUN_COMMAND` 的白名单**很窄**，实际只放行：

- `say ...`
- `seed`
- `list`
- `time query day` / `time query daytime` / `time query gametime`

`execute`、`function`、`setblock`、`fill`、`clone`、`schedule` 等间接绕过方式一律拒绝。**建筑和红石操作请使用结构化的 `PLACE_BLOCK` / `FILL`，不要指望 `RUN_COMMAND`。**

### 4.2 为什么有的动作标“禁止”

预览阶段服务端会逐条预检，失败的动作会显示 `禁止: <原因>` 且没有“确认”按钮。常见原因：

- 超出允许范围（无项目时是玩家 32 格内，有项目时必须在项目边界内）；
- 目标区块未加载（**不会自动加载区块**）；
- 超出世界高度或世界边界；
- 目标位置已有方块实体（箱子、熔炉等），为避免破坏容器数据而拒绝覆盖；
- 方块状态解析失败或带 NBT。

被禁止的动作**不影响同批其他动作**。

### 4.3 确认

点 **确认** 才会真正修改世界。执行前服务端会再检查一次：

- 你是否仍有权限（命令等级 2）；
- 范围是否仍然合法；
- **世界是否已被改动**——如果预览时的方块状态和现在不一致，会要求你重新生成预览。

这条“世界已变化”的检查是故意的：它防止你确认一个基于过期快照的计划。

### 4.4 撤销

方块动作执行成功后会显示 **撤销此操作**。

- 只能撤销最近 **8 次**操作，累计不超过 **32000** 个方块；
- 撤销前会检查目标方块是否仍等于当初写入的状态，被别人改过就拒绝；
- 含方块实体的位置拒绝撤销；
- 红石、流体、活塞、生物造成的**后续连锁变化不在撤销范围内**——快照只能还原方块本身。

## 5. 大型项目：草稿 → 批准 → 分阶段

建造远离玩家的大型结构时，走这条路：

### 5.1 先出草稿

AI 先返回一个 `projectDraft`（名称、目标、蓝图、维度、绝对坐标边界），**此时不会读取任何方块，也不会写入**。

### 5.2 你批准边界

右侧面板出现 **批准项目范围**，并显示具体边界坐标。**点它之前，世界写入范围仍然是 32 格。**

批准后：

- 该项目成为写入授权，动作校验从“玩家 32 格”切换为“**必须在项目边界内**”；
- 每轴最大 **512 格**；
- 每次写入仍需逐条确认，仍需命令等级 2 权限。

### 5.3 AI 读取局部窗口（focus）

批准后 AI 可以申请只读观察窗口：

- 单个窗口最多 **4096 个方块**、响应不超过 **48 KiB**；
- 窗口必须**落在已批准的项目边界内**；
- 只读方块状态（含朝向等属性），**不读容器库存、不读 NBT**；
- 遇到未加载区块会**直接报错**，不会假装是空气，也不会替你加载区块。

每次读取都会带时间戳和快照摘要。注意：**读取完成到你确认执行之间，世界仍可能变化**。

### 5.4 分阶段推进

大型项目拆成多个批次：每批最多 **16 个动作 / 8192 个方块**。每批单独预览、单独确认。

一批全部成功确认后，会出现 **确认阶段记录**。只有满足以下全部条件才会写入：

- 该计划里的每条动作都已处理（确认或拒绝）；
- 所有确认的动作都执行成功；
- 项目授权版本没有变过。

点 **继续下一阶段** 才会生成下一批，**不会自动往下执行**。

### 5.5 授权失效

以下情况会让旧预览立刻失效，必须重新生成：

- 重新批准了一个项目（替换）；
- 阶段记录被写入（版本 +1）；
- 世界在预览后发生了变化。

失效后你会看到“项目授权已变化，请重新生成预览”。检查清单会被清空，重新发一次任务即可。

## 6. 出错怎么办

| 现象 | 含义 | 怎么办 |
|---|---|---|
| HTTP 401 / 403 | 密钥无效或无权限 | 检查 API Key |
| HTTP 404 | 接口路径不对 | 检查 Endpoint，注意是否需要 `/v1` |
| HTTP 429 | 频率或额度受限 | 稍后点 **重试本轮** |
| HTTP 5xx | 服务端故障 | 稍后重试 |
| 请求超时 | 单次请求超过 60 秒 | 重试；或换更快的模型 |
| 模型返回内容无法解析为计划 | 模型没按 JSON 输出 | 点 **重试本轮**；换更强的模型；或用 `none` 思考强度 |
| 流式响应提前结束 | 连接中断 | 已收到的文本会保留，点 **重试本轮** |
| 等待世界上下文 | 还没收到服务端响应 | 点 **刷新世界** |
| 服务端未启用 MineCode 网络协议 | 服务器没装这个模组 | 客户端和服务端都要装 |

模型返回的“公开思考摘要”是它**主动给出的摘要**，不是完整的内部推理，也不保证详尽。

## 7. 多人服务器管理员

### 7.1 安装

客户端和服务端都要装 `minecode-1.0.0.jar` 和对应版本的 Fabric API。

### 7.2 权限

修改世界与撤销需要**命令等级 2**（相当于 gamemaster）。批准项目同样是授权闸门，也需要这个权限。

无权限的玩家可以打开控制台、聊天、读取上下文，但**不能**批准项目、确认动作或撤销。

### 7.3 API Key 与隐私

- API Key 只存在每个玩家自己的 `config/minecode.json`，**不经过服务器、不写进存档**；
- 世界档案（记忆、技能、审计日志）存在服务端存档目录；
- 服务器**看不到**玩家的密钥，但可以看到 AI 生成的计划和执行记录；
- 每个玩家有独立档案，互不可见。

### 7.4 数据文件

| 内容 | 路径 |
|---|---|
| 客户端设置（含密钥） | `<游戏目录>/config/minecode.json` |
| 世界档案 | `<存档>/data/minecode/<玩家UUID>.json` |
| 项目授权与检查点 | `<存档>/data/minecode/projects/<玩家UUID>.json` |

建议定期备份 `<存档>/data/minecode/`。

文件损坏时模组**拒绝覆盖**并报错，不会把档案静默清空——遇到这种情况直接恢复备份即可。

### 7.5 审计

有权限的玩家可以 `/minecode logs` 查看本玩家的审计日志（最近 256 条）。AI 的文本**不能**直接把世界操作标记为成功，只有服务端真实执行成功才会记账。

## 8. 已知限制

- **不保证红石逻辑正确**。快照只能还原方块，无法验证电路是否真的工作。复杂机器请先在测试存档里试。
- **指令动作不可撤销**。
- **不加载区块**。目标区块未加载就报错。
- **不读容器内容**。箱子、熔炉等方块实体不参与观察，也不能被覆盖或撤销。
- 单次任务最多 3 个子 Agent、每个最多 3 轮 focus 读取；预算用尽会以明确提示结束，不会无限重试。
- 模型名与参数支持因服务商而异，默认值只是可编辑的占位。
