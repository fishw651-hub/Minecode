# AI 注意力范围与大型项目

用户已选择“两层都做：自主聚焦 + 大项目分阶段建造”。现有客户端云端直连、最多三个子 Agent、逐条确认、撤销和档案边界继续适用。

## 方案比较

仅扩大半径可以放置远端方块，但不会让 AI 知道地形或保留工程进度。仅读取局部区域能改善上下文，但仍不能跨越原有 32 格限制。本次采用玩家批准项目边界、AI 自主读取内部窗口、多个小批次逐步完成的组合方案。

## 项目与注意力

项目保存名称、目标、总体蓝图、绝对坐标边界和维度。总体蓝图包含坐标原点、材料、分层/模块、红石端口坐标、朝向、信号类型、延迟与预留连接走廊。AI 提出项目草稿，玩家查看具体边界后批准。每轴最多 512 格，边界必须处于世界高度与边界内；批准只授予该玩家本项目内操作的空间范围，仍需等级 2 权限和逐条动作确认。重新批准替换项目，旧预览失效。

注意力窗口只控制读取，不扩大修改权限。AI 可在已批准项目内部选择窗口；无项目时窗口的整个区域必须处于玩家 32 格内。一次精读最多 4096 个方块，响应最多 48 KiB；palette 与连续长度编码保留空气与完整方块属性，超过预算明确要求缩小窗口。未加载区块返回错误而不是假定为空，不强制加载区块，不读取容器库存或 NBT。每次读取带时刻和快照摘要，读取与执行时世界仍可能变化。

## AI 协议与循环

在原 AiPlan JSON 上增加可选 `projectDraft`、`attentionRequests`、`checkpoint`；旧 JSON 与旧构造函数继续有效。Delegation 增加可选 `focus`。

- projectDraft：`name, goal, blueprint, bounds`。
- attentionRequests：`id, purpose, bounds`；bounds 使用 `x,y,z,x2,y2,z2` 绝对整数。
- checkpoint：`stage, summary, nextTask, complete`；只是待确认的阶段记录。

模型可以先返回 attentionRequests 与空 actions；编排器通过客户端网络读取服务端快照后再次请求同一 Agent。每 Agent 最多三轮读取，每轮最多三个窗口，整次编排最多 16 次模型请求与 16 次区域读取。预算耗尽保留可见记录并停止，不派遣无限任务。子 Agent 仍最多三个、深度一，写入不得越过自身 focus；汇总 Agent只汇总，禁止再派遣。

上下文仅包括项目总体蓝图、服务端实际执行记录、最近阶段记录、相关档案与当前窗口。去除重复 chatHistory 和审计历史；聊天长度、区域数据和汇总数据有明确字节预算，超出预算时报错或要求缩小方案，不悄悄截断动作坐标。总体蓝图不得在压缩时丢失。子 Agent获得共同约束与自己的窗口；完整本批动作保留供汇总，不把全部历史批次重发。

## 分阶段建造

保留单动作 4096、单批 8192 方块和最多 16 动作。大型项目拆分为多批，项目总尺寸不再受玩家移动后的 32 格限制。服务端以批准的完整包围盒校验，仍复查权限、维度、区块、世界高度/边界、方块实体和预览基线。

独立项目文件保存批准的蓝图、玩家确认的阶段与最近执行日志，不改变旧世界档案 schema。服务端记录成功、失败、拒绝、撤销；AI 的文本不能直接标记世界操作成功。阶段确认要求本批所有动作执行成功；下一阶段由玩家点击继续生成，不自动执行未确认动作。同批重叠动作成功后仅更新由本批明确修改的基线，外部改动仍要求重新预览。

撤销继续以已有目标方块快照为准：最近八个操作且累计最多 32000 个方块。界面明确保留上限。红石信号、流体、活塞或实体引发的间接变化不是完整事务，快照成功不表示红石逻辑已验证；必须重新观察相邻区域和接口。方块实体保护继续生效。

## 界面和网络

显示批准的项目边界、当前注意力区域、读取目的与阶段。AI 项目草稿显示“批准项目范围”；阶段完成显示“确认阶段记录”和“继续下一阶段”。focus 请求带 requestId 关联 Future；超时、取消、关闭面板、维度切换或请求替换后不能让旧快照进入新任务。项目批准后重新获取上下文。
